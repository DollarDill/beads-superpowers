@type=semantic:lesson @created=2026-07-19 @salience=3 @tags=worktrees,gitignore
lesson: git worktrees (git worktree add / bd worktree create) do NOT carry gitignored/untracked files into the new worktree — so .internal/ (specs, plans, reference, audits) is ABSENT there. A plan executed in a worktree that references .internal/ docs must copy them in first (mkdir + cp <main>/.internal/... <wt>/.internal/), or subagents silently implement from acceptance criteria alone, missing the verbatim design. @type=semantic:lesson @created=2026-07-07 @salience=3
When detecting if you're inside a git worktree, use 'git rev-parse --is-inside-work-tree' NOT '[ -d .git ]'. In a worktree, .git is a FILE pointing to .git/worktrees/<name> in the common dir, so the directory check returns false. Same pattern applies to .beads — use 'bd ready --limit 1' as a probe instead of '[ -d .beads ]'. Discovered during getting-up-to-speed validation, fixed in commit 3c00d8f.
