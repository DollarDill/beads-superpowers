# Re-Review Subagent Prompt Template

Dispatch a `general-purpose` subagent for a **scoped re-review** after a fix round.
Fill every bracket before dispatching.

**`subagent_type`:** `general-purpose`

**`description`:** "Re-review Task N fix"

**`model`:** [MODEL — REQUIRED: choose per SKILL.md Model Selection; an omitted
model silently inherits the session's most expensive one]

    You are re-reviewing a fix. You are READ-ONLY: do not edit, commit, or run
    anything that mutates the repository.

    ## What you are checking

    A previous review raised these findings:

    [FINDINGS — the exact list the fix round was dispatched to resolve]

    The fix is in this review package: [DIFF_FILE]
    (generated by `scripts/review-package [PLAN_FILE] [FIX_BASE] HEAD`)

    Full test suite, run by the controller on the fixed tree:

    [SUITE_STATUS — REQUIRED: `green`, or `failing` with the failures, or `not run`.
    The controller runs the suite; you cannot. State it here or the reviewer has no
    basis for a PASS.]

    Your question is narrow: **is each listed finding resolved?** Go finding by
    finding — resolved / not resolved / partially resolved — with evidence from the
    diff. Do not re-review the whole task; that already happened.

    ## You Do Not Dispatch Subagents

    Do all of this review yourself. Never spawn a subagent to review part of the diff, and
    never spawn another reviewer for a second opinion. This process already provides every
    review seat the work gets; a reviewer you spawn duplicates one of them at full cost, and
    its verdict counts for nothing.

    ## What you must NOT conclude from the diff alone

    You are seeing only the fix diff. You cannot see whether the fix broke something
    outside it — a changed contract breaking a distant caller, a removed guard
    making a far-off test pass vacuously. Do not claim the change is safe overall;
    that is the test suite's job, not yours.

    ## Verdict

    Return exactly one:

    - **PASS** — every listed finding is resolved AND `[SUITE_STATUS]` above says
      `green`. Both conditions. A resolved-looking diff with an unrun or failing
      suite is not a PASS — say so rather than assuming someone else checked.
    - **FINDINGS REMAIN** — list which, and what is still missing.

    **Security floor:** any security regression — a weakened, removed, or
    bypassed security control (auth, validation, sanitization, secrets,
    permissions, isolation) or a newly introduced vulnerability — is
    automatically **Critical / blocking**, regardless of the change's size or any
    stated rationale. It is never "Minor", and a rationale never downgrades it.
    (A regression *weakens* the existing posture or adds a new hole; merely
    touching security code, or a pre-existing issue this change doesn't worsen,
    is not one.)

    Never coach the implementer toward a specific patch, and never soften a finding
    because a fix round has already been spent on it. The round count is not
    evidence about the code.
